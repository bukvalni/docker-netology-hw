Домашнее задание к занятию "13.Системы мониторинга"

1. Минимальные метрики для платформы

CPU (процессор): Загрузка и очередь задач. Вычисления тяжелые — нужно видеть, справляется ли процессор.
Диск: Свободное место, количество файлов (inodes) и скорость записи. Отчеты сохраняются на диск, если место закончится — всё упадет.
HTTP: Количество запросов в секунду (RPS), время ответа (скорость) и ошибки (коды 4xx/5xx).
RAM (память): Объём свободной памяти, чтобы сервер не завис от перегрузки.

2. Как объяснить метрики менеджеру

CPU / RAM — насколько загружены «мозги» и «память» сервера.
Inodes — «лимит на количество файлов». Место на диске может быть, но если кончатся inodes — новый файл не создастся
Что предложить вместо технических терминов: Метрики качества SLA
Доступность: % успешных вычетов без сбоев.
Скорость: % отчетов, выдаваемых быстрее, например, 3 секунд.
Бюджет ошибок: сколько раз за месяц система может упасть без нарушения договора с клиентом.

3. Как отдать ошибки разработчикам без бюджета

Поставить Sentry (Self-Hosted): Это бесплатная программа, которая собирает только ошибки и удобные стеки вызовов прямо из кода.
Отправлять ошибки в Telegram / Slack: Настроить приложение так, чтобы при любой ошибке оно само слало сообщение в рабочий чат разработчиков.

4. В чем ошибка в формуле SLA (почему показывает 70%)

В формуле 2xx / все_запросы не учтены ответы 3xx (редиректы и кэш, например 304 Not Modified).
Ответы 3xx — это успешные запросы, но формула считает их за ошибки, потому что делит только 2xx на общее число
Правильная формула: (2xx + 3xx) / все запросы

5. Плюсы и минусы Pull и Push

Pull (сервер сам забирает данные):
Плюс: Сервер контролирует нагрузку и сразу видно, если какой-то узел умер и не отвечает
Минус: Сложно собирать данные с быстро закрывающихся задач и из-за закрытых сетевых экранов (NAT/Firewall)
Push (агенты сами отправляют данные):
Плюс: Отлично подходит для коротких задач и легко проходит через защищенные сети
Минус: Если тысячи агентов одновременно отправят данные, они могут уронить сервер мониторинга

6. Какая система к чему относится

Prometheus: Pull (забирает сам; для коротких задач есть костыль Pushgateway).
TICK: Push (агент Telegraf сам отправляет данные).
Zabbix: Гибрид (умеет и запрашивать сам, и принимать от агентов).
VictoriaMetrics: Гибрид (может сама забирать данные или принимать отправленные).
Nagios: Гибрид (базово сам опрашивает, но умеет принимать пассивные чеки).
